## Step 1: Exam Blueprint & Test-Taking Mechanics (Trainings #1–#4)

- **Score to Pass:** **700 / 1,000** (compensatory scoring — you don't have to pass every individual domain, only the overall exam).
- **Question Breakdown:** 65 questions total in **90 minutes** (50 scored + 15 unscored). Never leave a question blank — no guessing penalty.
- **Question Types:**
  - *Multiple Choice:* 1 correct answer, 3 distractors.
  - *Multiple Response:* 2+ correct answers out of 5+ options. Read carefully for **"Choose TWO"** or **"Choose THREE"**.
- **Out of Scope (Don't waste time memorizing):** Writing code, complex architecture design, deep CLI troubleshooting, load/performance testing, Game Tech (GameLift), Media Services (Elemental/IVS), and Robotics (RoboMaker).

## Step 2: Domain-by-Domain Study Guide (Trainings #5–#15 & #19)

### Domain 1: Cloud Concepts — 24% (Trainings #5, #6, #7)

#### Task 1.1: Benefits of the AWS Cloud (The 6 Advantages)
1. **Trade fixed expense (CapEx) for variable expense (OpEx):** Pay only for what you consume instead of buying physical servers upfront.
2. **Massive economies of scale:** AWS aggregates usage from millions of customers to lower prices.
3. **Stop guessing capacity:** Scale elastically up and down instead of over-provisioning or running out.
4. **Increase speed and agility:** Provision IT resources in minutes, enabling rapid experimentation.
5. **Stop spending money running/maintaining data centers:** Focus on differentiating business value, not racking servers.
6. **Go global in minutes:** Deploy apps in multiple AWS Regions worldwide with low latency.

- **Key Terms to Distinguish:**
  - **High Availability:** System stays operational with minimal downtime even if a component fails (e.g., Multi-AZ).
  - **Elasticity:** Automatically scaling resources *up and down* to match demand (Auto Scaling).
  - **Agility:** Ability to develop, test, and launch new applications rapidly.
  - **Fault Tolerance:** Built-in redundancy so a failure causes *zero* interruption.

#### Task 1.2: AWS Well-Architected Framework (6 Pillars)
1. **Operational Excellence:** Run & monitor systems, operations as code, small/reversible changes, anticipate failure, game days.
2. **Security:** Least privilege, traceability, security at all layers, automate security best practices, encrypt in transit & at rest.
3. **Reliability:** Automatic recovery from failure, test recovery procedures, horizontal scaling, stop guessing capacity.
4. **Performance Efficiency:** Democratize advanced tech, go global in minutes, use serverless, experiment often, mechanical sympathy.
5. **Cost Optimization:** Cloud Financial Management, consumption model, measure overall efficiency, analyze/attribute spend, managed services.
6. **Sustainability:** Maximize utilization (rightsizing/serverless), adopt efficient hardware (AWS Graviton), minimize downstream impact.

#### Task 1.3: Cloud Migration & AWS CAF
- **AWS Cloud Adoption Framework (AWS CAF) — 6 Perspectives:**
  - *Business Capabilities:* **Business**, **People**, **Governance**
  - *Technical Capabilities:* **Platform**, **Security**, **Operations**
  - *Business Outcomes:* Reduced business risk, improved ESG performance, increased revenue, increased operational efficiency.
- **Migration Strategies (The 7 Rs):**
  - **Rehost** ("Lift and Shift" — fast, move as-is, e.g., AWS Application Migration Service).
  - **Replatform** ("Lift, Tinker, and Shift" — minor cloud optimizations like moving self-managed DB to RDS).
  - **Refactor / Re-architect** (Redesign using cloud-native/serverless to maximize agility/cost).
  - **Repurchase** ("Drop and Shop" — move to SaaS, e.g., Salesforce or AWS Marketplace).
  - **Relocate** (Hypervisor-level lift & shift, e.g., VMware Cloud on AWS).
  - **Retain** (Keep on-prem for now due to compliance/dependencies).
  - **Retire** (Decommission unused apps).
- **Migration Tools:**
  - **AWS Snow Family** (Snowcone, Snowball Edge, Snowmobile): Physical devices for petabyte/exabyte offline data transfer or edge compute in disconnected environments.
  - **AWS DMS (Database Migration Service):** Migrates databases with minimal downtime (homogeneous or heterogeneous).
  - **AWS SCT (Schema Conversion Tool):** Converts database schemas between *different* engines (e.g., Oracle → PostgreSQL).
  - **AWS Migration Hub:** Single dashboard to track migration progress across tools.

#### Task 1.4: Cloud Economics
- **Rightsizing:** Matching instance types/sizes to actual workload performance and capacity needs (use **AWS Compute Optimizer**).
- **Licensing:** BYOL (Bring Your Own License — often paired with EC2 Dedicated Hosts) vs. License Included (AWS provides license, e.g., Windows/SQL Server on EC2/RDS).
- **Automation & Managed Services:** Use **AWS CloudFormation** (IaC) for repeatable provisioning; offload undifferentiated heavy lifting to managed services (RDS, ECS, EKS, DynamoDB).

### Domain 2: Security and Compliance — 30% (Trainings #8, #9, #10)

#### Task 2.1: AWS Shared Responsibility Model
- **AWS ("Security OF the Cloud"):** Physical security, data center facilities, hardware, networking infrastructure, virtualization/hypervisor layer.
- **Customer ("Security IN the Cloud"):** Customer data, IAM users/roles/policies, client-side & server-side encryption, OS/network/firewall configuration (Security Groups, NACLs), guest OS patching (on EC2).
- **Shared Controls:** Patch Management, Configuration Management, Awareness & Training.
- **Shift by Service:**
  - *EC2 (Infrastructure):* Customer patches OS & apps.
  - *RDS (Managed):* AWS patches OS & DB engine; customer manages data, schema, and access.
  - *S3 / Lambda / DynamoDB (Abstracted):* AWS manages infrastructure & platform; customer manages data, encryption choices, and IAM permissions.

#### Task 2.2: Security, Governance, & Compliance Services
| Service | 1-Line Exam Definition |
| :--- | :--- |
| **AWS Artifact** | Self-service portal for on-demand **compliance reports** (SOC, PCI, ISO) and **agreements** (BAA/HIPAA). |
| **AWS CloudTrail** | **Auditing & Governance** — logs *who did what* (all API calls & Console actions). |
| **Amazon CloudWatch** | **Monitoring & Observability** — tracks metrics (CPU, memory), logs, alarms, dashboards. |
| **AWS Config** | Records & evaluates **resource configuration changes** over time against compliance rules. |
| **AWS Audit Manager** | Continuously audits AWS usage to simplify **risk and compliance assessments** (evidence collection). |
| **Amazon GuardDuty** | Intelligent **threat detection** (uses ML to analyze CloudTrail, VPC Flow Logs, DNS logs). |
| **Amazon Inspector** | Automated **vulnerability management** — scans EC2, Lambda, and ECR container images for CVEs/network exposure. |
| **Amazon Macie** | Uses ML to discover & protect **sensitive data (PII)** stored in **Amazon S3**. |
| **AWS Security Hub** | Central **single-pane-of-glass** aggregating security findings from GuardDuty, Inspector, Macie, etc. |
| **Amazon Detective** | Investigates **root cause** of security findings using graph analysis. |
| **AWS Shield** | Managed **DDoS protection** (Standard = free automatic L3/L4; Advanced = paid + 24/7 Shield Response Team + cost protection). |
| **AWS WAF** | **Web Application Firewall** (Layer 7) — blocks SQL injection, XSS, bad IPs on CloudFront/ALB/API Gateway. |
| **AWS KMS** | Managed service to create & control **encryption keys** (multi-tenant HSMs). |
| **AWS CloudHSM** | **Single-tenant** dedicated hardware security module (customer has exclusive key control). |
| **AWS Certificate Manager (ACM)** | Provisions & auto-renews **SSL/TLS certificates** (encryption in transit). |

#### Task 2.3: Access Management (IAM)
- **Root User Best Practices:** Lock it away! Enable **MFA**, **never** create access keys for root, don't use for daily tasks, create an IAM admin user/group instead.
  - *Tasks ONLY Root can do:* Close account, change AWS Support plan, modify root email/password, restore IAM user permissions.
- **IAM Components:** Users (individuals), Groups (collections of users), **Roles** (temporary credentials for EC2, Lambda, or cross-account access — *never hardcode keys on EC2!*), Policies (JSON permissions following **Least Privilege**).
- **AWS IAM Identity Center (formerly AWS SSO):** Centralized workforce access (federated SSO) across multiple AWS Organizations accounts and business apps.
- **Amazon Cognito:** Authentication/authorization for **web & mobile app end-users** (millions of customers, social logins).
- **Credential Storage:**
  - **AWS Secrets Manager:** Stores DB passwords/API keys with **automatic rotation** (paid).
  - **AWS Systems Manager Parameter Store:** Stores config data & secrets (free standard tier, no native auto-rotation).

#### Task 2.4: Network Security & Resources
- **Security Groups:** Stateful firewall at the **instance (ENI) level**; **allow rules only** (return traffic automatically allowed).
- **Network ACLs (NACLs):** Stateless firewall at the **subnet level**; supports **both allow and deny rules** (evaluated in numbered order).
- **AWS Trusted Advisor:** Inspects your account and gives real-time recommendations across 5 categories (Cost Optimization, Performance, Security, Fault Tolerance, Service Limits).
- **AWS Abuse / Trust & Safety Team:** Report suspected abuse of AWS resources (phishing, DDoS originating from AWS IPs).

### Domain 3: Cloud Technology and Services — 34% (Trainings #11, #12, #13)

#### Task 3.1: Deploying & Accessing AWS
- **Access Methods:** AWS Management Console (GUI), AWS CLI (scripting/automation), AWS SDKs (code/APIs), **CloudShell** (browser-based pre-authenticated shell), **CloudFormation** (Infrastructure as Code).
- **Deployment Models:** Cloud-native (all-in AWS), Hybrid (on-prem + AWS via VPN/Direct Connect/Outposts), On-premises (private cloud).

#### Task 3.2: AWS Global Infrastructure
- **Region:** Physical geographic area containing **3+ isolated Availability Zones** (choose based on: Compliance/Data Sovereignty, Proximity/Latency, Service Availability, Pricing).
- **Availability Zone (AZ):** 1 or more discrete data centers with redundant power/networking; separated by meaningful distance (<100 km) so they don't share single points of failure.
- **Edge Locations:** Points of Presence used by **Amazon CloudFront** (CDN caching) and **Route 53** to deliver content with ultra-low latency.
- **AWS Local Zones:** Places compute/storage closer to large metro populations for single-digit millisecond latency.
- **AWS Wavelength:** Embeds AWS compute/storage inside **5G telecom carrier networks**.
- **AWS Outposts:** Brings physical **AWS-managed hardware racks** into your on-premises data center.

#### Task 3.3: Compute Services
- **EC2 Instance Families:** General Purpose (`M`, `T`), Compute Optimized (`C`), Memory Optimized (`R`, `X`), Accelerated Computing/GPU (`P`, `G`), Storage Optimized (`I`, `D`).
- **Containers:** **Amazon ECR** (Docker image registry), **Amazon ECS** (AWS-native container orchestrator), **Amazon EKS** (managed Kubernetes), **AWS Fargate** (**serverless** compute engine for ECS/EKS — no EC2 servers to manage).
- **Serverless:** **AWS Lambda** (event-driven functions, pay per request & compute duration, max 15-min runtime).
- **PaaS / Simple Compute:** **AWS Elastic Beanstalk** (upload code, AWS handles provisioning/LB/scaling; you still have underlying EC2 control), **Amazon Lightsail** (simple predictable-pricing VPS for small websites/apps), **AWS Batch** (fully managed batch processing jobs).
- **Elasticity & Traffic:** **Amazon EC2 Auto Scaling** (adds/removes instances automatically) + **Elastic Load Balancing (ELB)** (distributes incoming traffic across healthy targets in multiple AZs).

#### Task 3.4: Database Services
| Service | Type | Best Exam Use Case |
| :--- | :--- | :--- |
| **Amazon RDS** | Managed Relational (SQL) | MySQL, PostgreSQL, MariaDB, Oracle, SQL Server; Multi-AZ for HA, Read Replicas for read scaling |
| **Amazon Aurora** | Cloud-Native Relational | MySQL/PostgreSQL compatible; **5x faster than MySQL, 3x faster than PostgreSQL**, auto-scaling storage up to 128 TB |
| **Amazon DynamoDB** | Serverless NoSQL (Key-Value/Doc) | Single-digit millisecond latency at any scale, fully managed |
| **Amazon MemoryDB for Redis** | In-Memory (Durable) | Microsecond reads, single-digit ms writes, Redis-compatible |
| **Amazon Neptune** | Managed Graph DB | Social networks, fraud detection, recommendation engines |
| **Amazon Redshift** | Data Warehouse (OLAP) | Petabyte-scale SQL analytics & BI reporting |

#### Task 3.5: Networking & Content Delivery
- **Amazon VPC:** Logically isolated virtual network (Public Subnets = have route to **Internet Gateway [IGW]**; Private Subnets = outbound internet via **NAT Gateway**).
- **Amazon Route 53:** Highly available managed **DNS** service + domain registration + health checks.
- **Amazon CloudFront:** Global **CDN** caching static/dynamic content at Edge Locations.
- **AWS Global Accelerator:** Routes traffic over the AWS global private network using **static Anycast IPs** for improved performance/availability (non-HTTP/TCP/UDP too).
- **Connectivity:** **AWS Site-to-Site VPN** (encrypted tunnel over *public internet*, fast to set up) vs. **AWS Direct Connect** (dedicated *private physical fiber*, consistent bandwidth, weeks/months to provision).
- **Amazon API Gateway:** Fully managed front door to create, publish, and secure REST/WebSocket APIs.

#### Task 3.6: Storage Services
- **Amazon S3 (Object Storage):** Unlimited scale, **11 nines (99.999999999%) durability**, max object size 5 TB.
  - *Storage Classes:* **Standard** (frequent) → **Intelligent-Tiering** (unknown/changing access patterns) → **Standard-IA** (infrequent, rapid access) → **One Zone-IA** (recreatable infrequent, 1 AZ) → **Glacier Instant Retrieval** (ms archive) → **Glacier Flexible Retrieval** (mins–hours) → **Glacier Deep Archive** (lowest cost, 12–48 hrs).
  - *Lifecycle Policies:* Automatically transition objects to cheaper tiers or expire/delete them.
- **Block Storage:** **Amazon EBS** (persistent network-attached virtual hard drive tied to a **single AZ**; snapshots stored in S3) vs. **EC2 Instance Store** (ephemeral/temporary physically attached disk — data lost on stop/terminate).
- **File Storage:** **Amazon EFS** (serverless, elastic **Linux NFS** file share mounted across multiple AZs) vs. **Amazon FSx** (managed **Windows File Server**, Lustre for HPC, NetApp ONTAP, OpenZFS).
- **Hybrid & Backup:** **AWS Storage Gateway** (connects on-prem apps to cloud storage with local caching) + **AWS Backup** (centralized backup policy management across AWS services).

#### Task 3.7: AI/ML & Analytics Services
- **AI/ML (Memorize the 1-word trigger!):**
  - **SageMaker** = Build, train, deploy custom ML models.
  - **Comprehend** = NLP (sentiment analysis, entity extraction).
  - **Kendra** = Intelligent enterprise **search**.
  - **Lex** = Conversational **chatbots** (powers Alexa).
  - **Polly** = **Text-to-Speech**.
  - **Transcribe** = **Speech-to-Text**.
  - **Translate** = Language translation.
  - **Rekognition** = **Image & video** analysis (faces, objects, moderation).
  - **Textract** = Extract text/tables/forms from **scanned documents/PDFs** (smart OCR).
- **Analytics:**
  - **Amazon Athena:** **Serverless SQL queries** directly on data in **S3** (pay per TB scanned).
  - **AWS Glue:** Serverless **ETL** (Extract, Transform, Load) + Data Catalog.
  - **Amazon Kinesis:** Real-time **streaming data** ingestion & analytics.
  - **Amazon MSK:** Managed **Apache Kafka** streaming.
  - **Amazon EMR:** Managed **Hadoop / Spark** big data clusters.
  - **Amazon OpenSearch Service:** Search, log analytics, and visualization.
  - **Amazon QuickSight:** Serverless **BI dashboards** & visualizations.
  - **AWS Data Exchange:** Find, subscribe to, and use third-party datasets.

#### Task 3.8: Other In-Scope Services (Quick Hits)
- **App Integration:** **SQS** (decoupled message **queue** — pull), **SNS** (pub/sub **notifications** — push email/SMS/Lambda), **EventBridge** (serverless **event bus** routing events from AWS/SaaS), **Step Functions** (visual workflow **orchestration**).
- **Business Apps:** **Amazon Connect** (cloud **contact/call center**), **Amazon SES** (bulk/transactional **email**).
- **Developer Tools (CI/CD):** **CodeCommit** (Git repo), **CodeBuild** (compile/test), **CodeDeploy** (deploy to EC2/Lambda), **CodePipeline** (CI/CD orchestration), **CodeArtifact** (package registry), **Cloud9** (cloud IDE), **X-Ray** (distributed tracing/debugging), **AppConfig** (feature flags/config deployment).
- **End-User Computing:** **WorkSpaces** (managed cloud **virtual desktops**), **AppStream 2.0** (stream desktop **applications** to a browser), **WorkSpaces Web** (secure browser access).
- **Frontend/Mobile & IoT:** **AWS Amplify** (build/host full-stack web & mobile apps), **AWS AppSync** (managed GraphQL APIs), **Device Farm** (test mobile/web apps on real devices), **IoT Core** (connect IoT devices to AWS), **IoT Greengrass** (run AWS compute/ML locally on edge IoT devices).
- **Customer Engagement:** **AWS IQ** (hire certified third-party AWS freelancers), **AWS Managed Services (AMS)** (AWS operates your cloud infrastructure for you), **AWS Activate** (credits/support for startups).

### Domain 4: Billing, Pricing, and Support — 12% (Trainings #14, #15)

#### Task 4.1: Pricing Models
- **EC2 Options:** On-Demand (spiky/short-term) | Savings Plans (1–3 yr $/hr commitment; Compute SP = most flexible) | Reserved Instances (1–3 yr steady-state; Standard vs Convertible) | Spot (up to 90% off, interruptible with 2-min notice) | Dedicated Hosts (physical server, BYOL/compliance) | Dedicated Instances (isolated hardware, no socket visibility).
- **Data Transfer:** Inbound from internet = **$0**. Outbound to internet & cross-Region/cross-AZ = **charged**.

#### Task 4.2: Billing, Budget, & Cost Management Tools
- **AWS Pricing Calculator:** Estimate costs *before* building.
- **AWS Cost Explorer:** Analyze historical spend & forecast 12 months ahead.
- **AWS Budgets:** Set cost/usage thresholds & trigger **alerts** (or automated actions).
- **AWS Cost and Usage Report (CUR):** Most detailed line-item billing CSV/Parquet files (to S3).
- **AWS Billing Conductor:** Customize billing rates/chargebacks for internal departments or MSP clients.
- **AWS Organizations:** Consolidated billing across accounts + **volume pricing tiers** + **shared RIs/Savings Plans** + Service Control Policies (SCPs).
- **Cost Allocation Tags:** Key-value labels (e.g., `Department=Finance`) activated in Billing Console to break down costs in Cost Explorer & CUR.

#### Task 4.3: Support Plans & Technical Resources
- **Support Tiers:**
  - **Basic (Free):** Account/billing support, 7 Core Trusted Advisor checks, AWS Health Dashboard.
  - **Developer:** Business-hours email support (<12h System Impaired), 7 Core Trusted Advisor checks.
  - **Business:** 24/7 phone/chat/email (<1h Production Down), **Full Trusted Advisor checks**, AWS Support API.
  - **Enterprise On-Ramp:** Everything in Business + **Pooled TAMs**, Concierge Support, 1 IEM/year, <30m Business-Critical Down.
  - **Enterprise:** Everything in Business + **Dedicated TAM**, Concierge Support, IEM included, **<15m Business-Critical Down**.
- **AWS Technical Resources:** **AWS Prescriptive Guidance** (migration/modernization playbooks), **AWS Knowledge Center** (official Q&A troubleshooting), **AWS re:Post** (community Q&A forum), **AWS Professional Services** (AWS consultants), **AWS Partner Network (APN)** (ISVs & System Integrators), **AWS Marketplace** (curated third-party software catalog).
